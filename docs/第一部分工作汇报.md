# 二、数据是怎么来的？

## 2.1 两类数据源

### 数据一：台风路径数据

**来源**：中国气象局官方数据

**内容**：记录了每场台风在什么时间、什么位置、有多强

**类比**：就像记录一个人每天的GPS位置和体温

```
示例数据：
台风编号: 1410 (2014年第10号台风)
时间: 2014-07-17 00:00
位置: 北纬9.8°, 东经136.0°
中心气压: 1002 hPa
最大风速: 15 m/s
```

**我们处理了什么**：
- 原始数据每6小时记录一次 → 我们插值成每30分钟一次（更精细）
- 计算了台风移动速度、移动方向、路径弯曲程度等派生特征

### 数据二：降水卫星数据

**来源**：NASA的GPM降水测量卫星

**内容**：卫星拍摄的降水分布图像（类似热力图）

**类比**：就像卫星给地球"拍照片"，照片上每个像素的颜色深浅代表那里下了多少雨

```
示例理解：
一张图片覆盖约1000km × 1000km的区域
每个像素约10km × 10km
像素值 = 该位置的降水强度 (mm/h)
```

**我们处理了什么**：
- 从每张图片中提取：总降水量、最大降水强度、极端降水面积等
- 计算了降水中心相对于台风中心的偏移距离
- 计算了降水分布的对称性指数

# 三、第一问我们发现了什么？

## 3.1 关键结论（大白话版）

### 结论1：台风越强，极端降水面积越大

**发现**：最大风速和极端降水面积（每小时超过20mm的区域）有明显的正相关关系。

**通俗理解**：台风就像一个"降雨机器"，机器功率越大（风速越快），能制造暴雨的范围就越大。

### 结论2：降水中心通常不在台风正中心

**发现**：降水中心相对于台风中心有偏移，平均偏移距离约2000多公里。

**通俗理解**：台风的"雨"不是均匀分布在台风周围的，而是偏向某一侧。这和台风的移动方向、周围环境气流有关。

### 结论3：降水分布很不均匀

**发现**：非对称性指数普遍大于1，说明降水在四个象限分布差异很大。

**通俗理解**：台风的雨不是"转着圈均匀下"，而是某些方向雨特别大，某些方向雨很小。

## 3.2 有意思的发现

### 发现1：路径曲率有阈值效应

**现象**：当台风路径弯曲程度超过某个值时，降水特征会发生明显变化。

**可能原因**：路径弯曲意味着台风在转向，转向时速度通常会减慢，给某地区带来更长时间的影响。

### 发现2：6小时变化量的预测价值

**现象**：气压和风速的6小时变化量对预测降水变化有重要参考价值。

**通俗理解**：台风"正在变强"还是"正在变弱"的信息，比当前有多强更能预测接下来的降水。

### 发现3：移动速度影响持续时间

**现象**：移动速度慢的台风，虽然瞬时降水不一定更大，但累积影响时间更长。

**实际意义**：一个移动缓慢的台风可能带来更严重的洪涝灾害。

## 3.3 我们分析了什么

### 分析方法一：相关性分析

**做了什么**：计算了所有特征之间的Spearman相关系数

**结果形式**：一个热力图矩阵

**怎么读**：
- 红色/蓝色越深 = 相关性越强
- 正相关 = 一个变大，另一个也变大
- 负相关 = 一个变大，另一个变小

### 分析方法二：随机森林重要性

**做了什么**：用随机森林模型预测极端降水面积，看哪些特征最重要

**结果形式**：特征重要性排名柱状图

**怎么读**：柱子越长，这个特征对预测越重要

### 分析方法三：SHAP解释

**做了什么**：分析每个特征具体是怎么影响预测结果的

**结果形式**：SHAP依赖曲线

**怎么读**：
- X轴 = 特征的取值
- Y轴 = 这个取值对预测的贡献
- 可以看出非线性的阈值效应

## 4.3 常见问题解决

### 问题1：找不到文件

**错误信息**：`FileNotFoundError`

**解决方法**：
1. 检查数据文件夹是否在正确位置
2. 检查脚本中的路径是否正确
3. Windows路径注意用 `r"路径"` 或双反斜杠

### 问题2：内存不足

**错误信息**：`MemoryError`

**解决方法**：
1. 关闭其他程序释放内存
2. 分批处理数据（修改代码）
3. 使用更小的数据子集测试

### 问题3：中文显示乱码

**现象**：图表中的中文显示为方框

**解决方法**：
1. 确保系统安装了SimHei字体
2. 或修改代码使用其他中文字体

### 问题4：SHAP计算太慢

**现象**：step1.4运行很久

**解决方法**：
1. 这是正常的，SHAP计算本身较慢
2. 可以先用少量数据测试
3. 确保使用的是TreeExplainer（代码中已使用）

# 五、改进建议（第二轮工作方向）

## 5.1 数据层面的改进

### 改进1：补充外部环境数据

**现状**：目前只有台风自身特征和降水特征

**建议补充**：

| 数据类型 | 用途 | 获取途径 |
|----------|------|----------|
| 海陆分布 | 判断台风是否在海上 | GSHHG海岸线数据 |
| 地形高程 | 地形对降水的影响 | SRTM高程数据 |
| 海表温度 | 影响台风强度 | ERA5再分析数据 |
| 风切变 | 影响台风发展 | ERA5再分析数据 |

**预期效果**：模型能考虑更多物理因素，预测更准确

### 改进2：数据质量检查

**建议**：
1. 检查异常值（如风速突然从50变到10又变回50）
2. 检查缺失值的分布模式
3. 对不同年份的数据进行一致性检查

## 5.2 模型层面的改进

### 改进1：实现迭代残差LSTM

**核心思想**：
```
第一轮：用一个简单模型预测 → 得到baseline
第二轮：用LSTM学习baseline的误差 → 修正预测
第三轮：继续学习剩余误差 → 进一步修正
...
```

**为什么好**：
- 每一轮只需要学习"残差"，任务更简单
- 可以逐步逼近真实值
- 类似于"错题本"——每次改正之前的错误

### 改进2：多时效联合预测

**核心思想**：一个模型同时预测6小时后、12小时后、24小时后的状态

**为什么好**：
- 不同时效的预测共享底层特征
- 训练时互相约束，提高整体准确性

### 改进3：物理约束

**建议**：
1. 预测的位置变化不能超过物理极限（台风不可能瞬间移动几千公里）
2. 登陆后强度必须衰减
3. 降水与强度正相关

## 5.3 可视化层面的改进

### 改进1：降水空间分布图

**现状**：目前只有统计图表

**建议增加**：
- 在地图上展示预测的降水分布
- 类似天气预报中的降水色斑图

### 改进2：时空演化动画

**建议**：
- 制作台风移动+降水变化的动画
- 直观展示台风生命周期的演变

### 改进3：不确定性可视化

**建议**：
- 预测结果不只是单一值，而是给出置信区间
- 在图上用颜色深浅或误差棒表示不确定性

# 七、关键概念速查

| 术语 | 通俗解释 |
|------|----------|
| 三次样条插值 | 用平滑曲线连接离散的点，得到中间值 |
| Spearman相关系数 | 衡量两个变量是否"一起变化"，不要求线性关系 |
| 随机森林 | 很多决策树投票决定结果，能评估特征重要性 |
| SHAP值 | 解释每个特征对预测结果的贡献大小 |
| LSTM | 一种能"记住"历史信息的神经网络，适合预测时间序列 |
| 残差学习 | 每次只学习之前的错误，逐步改进 |
| 多时效预测 | 一次预测多个时间点的结果 |
