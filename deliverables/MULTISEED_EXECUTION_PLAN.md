## 3. Orchestration contract (seed-only override, dry-run, resumable, fail-fast)

The runner at `scripts/run_multiseed_core.py` enforces every line
below at import time or at run time. No run may deviate.

| Requirement                                                                                                              | How it is enforced                                                                                                                |
|--------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------|
| `seed` is the only scientific field allowed to change across runs.                                                        | `validate_seed_only_override(cfg, path)` re-checks every frozen common control (`FROZEN_COMMON` minus `training.seed`) before each row starts and refuses to launch if any non-seed frozen field deviates. The runner then sets `cfg["training"]["seed"] = new_seed` only. |
| Test split is never loaded. Evaluator called with `split="val", test_status="SEALED"`.                                   | Hardcoded `EVALUATOR_SPLIT = "val"`, `EVALUATOR_TEST_STATUS = "SEALED"`. `assert_test_seal()` raises at import time if either drifts, or if `"test"` ever appears in any allowed-split allow-list. |
| Resumable: compatible artifact dir is auto-skipped on re-run.                                                              | `check_compatibility(out_dir, row)` returns `COMPLETE` iff both `manifest.json` and `result_v2.json` exist and every contract check below passes. The runner only SKIPs rows whose status is `COMPLETE`. |
| Incomplete run is never silently skipped.                                                                                 | If `manifest.json` exists but `result_v2.json` is missing, or any contract check fails, the status is `INCOMPLETE` with the failed checks enumerated. The runner reports it; Phase 2 will not start with `INCOMPLETE` rows present. |
| Each row gets an independent per-seed output directory.                                                                  | `output_root / seed_<s> / <alias>/` (alias = `I2`, `I3`, ...; never the canonical stem). `I5` and `P0` share the `I5/` dir but the manifest records both aliases. |
| Failure is explicit.                                                                                                       | Per-row exceptions surface to the CLI with `status=INCOMPLETE` and the exact failure list. `--execute` refuses to start if any row is `INCOMPLETE`. |
| Artifact verification matches the canonical verifier.                                                                     | The compatibility contract mirrors the checks in `scripts/verify_experiment_artifact.py` plus the `result_v2.json` inner contract (`protocol_id`, `test_status`, `split`, `n_events`, `n_windows`). |
| `smoke == false`.                                                                                                          | Required by the verifier; a `smoke == true` artifact is reported `INCOMPLETE`. |
| Manifest fields match canonical schema.                                                                                     | `experiment`, `model`, `seed`, `batch_size=4`, `epochs=20`, `test_status=SEALED`, `protocol_id=evaluation_v2`, `input_channel_indices`, `loss_components`. |
| `result_v2.json` inner matches canonical v2 contract.                                                                     | `protocol_id="evaluation_v2"`, `test_status="SEALED"`, `split="val"`, `n_events=7`, `n_windows=1266`. |
| Channel subsets and loss components are read from the canonical YAML, never hardcoded.                                    | `build_run_matrix()` resolves aliases via the alias registry and reads `input_channel_indices` / `physics_loss.components` from each `configs/experiments/<stem>.yaml`. |
| No test mode flag is exposed.                                                                                              | The runner never instantiates a test `DataLoader`. `_test_ids` returned from `load_split` is discarded (`train_ids, val_ids, _test_ids`). |
| Dry-run by default; training requires an explicit `--execute` switch.                                                     | `--dry-run` is the default; the executor path is gated behind `--execute`. Phase 1 never invokes training. |

### 3.1 Compatibility check (skip-completed decision)

`check_compatibility(out_dir, row)` returns one of:

- **`COMPLETE`** — all of the following hold:
  - `manifest.json` and `result_v2.json` both exist and parse.
  - `manifest.experiment == row.canonical_stem`
  - `manifest.seed == row.seed`
  - `manifest.batch_size == 4`, `manifest.epochs == 20`
  - `manifest.test_status == "SEALED"`
  - `manifest.smoke == False`
  - `manifest.input_channel_indices == row.channels`
  - `manifest.loss_components == row.loss_components`
  - `manifest.protocol_id == "evaluation_v2"`
  - `manifest.model == row.model_name`
  - `result_v2.result.protocol_id == "evaluation_v2"`
  - `result_v2.result.test_status == "SEALED"`
  - `result_v2.result.split == "val"`
  - `result_v2.result.n_events == 7`
  - `result_v2.result.n_windows == 1266`
- **`INCOMPLETE`** — at least one of the above fails. The `failed_checks`
  list is reported. NEVER skipped.
- **`MISSING`** — either `manifest.json` or `result_v2.json` is absent.

python scripts/run_multiseed_core.py --dry-run                      # default; Phase 1

`--dry-run` and `--verify-only` differ only in that `--verify-only`
calls `check_compatibility` against every per-seed directory (useful
once Phase 2 has started and partial runs need scanning). `--dry-run`
also calls it; the two flags are functionally equivalent today and
kept separate for clarity in the orchestration contract.
